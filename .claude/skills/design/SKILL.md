# 설계

**번들(실행 세션 하나가 연달아 치는 청크 4~8개) 앞에 한 번 한다.** 코드를 안 건드린다.
결과물은 `PLAN.md` 의 행과 「구간 > 번들」 표의 한 줄이다 — 실행 세션(Opus)이 그 행만 읽고 **멈추지 않고** 간다.

**근거는 이 저장소의 세 번이다.** 번들 A(2026-09-23 밤)는 설계가 행마다 결정·번호 절차·닫힘·실패 사다리를 적었고
여덟 청크를 실행 중 정지 0 으로 쳤다 — 여덟 중 넷이 행과 다르게 갔고 그 자리를 행에 적었다.
2026-09-25 에 도구 번들(`Q215`~`Q220`)과 게이트 맹점(`Q221`~`Q228`)을 같은 방식으로 설계했다.
ProjectTicket `B0` 가 번들 A 를 근거로 이 스킬을 먼저 세웠고 `Q219` 가 옮겼다.

**설계와 실행을 한 세션에서 할 때는 이 스킬이 아니다** — `.claude/prompts/bundle-session.md` 가 그 여는 말이다.
이 스킬은 설계를 떼어 다른 세션(Fable)이 할 때다.

## 절차

| 순서 | 무엇 | 남기는 것 |
|---|---|---|
| 1 | **깨진 것부터 본다** — `origin/main` 의 CI 가 빨갛거나 `진행중` 청크가 있으면 번들보다 먼저다 | 있으면 그것이 번들의 첫 행 |
| 2 | **조건이 찬 기준 문서가 있나 본다**(`CLAUDE.md` 「문서가 코드보다 먼저다」) — 있으면 코드 행보다 앞에 둔다 | 그 D 행 |
| 3 | 번들 후보를 고른다 — 선행이 `완료` 인 미착수 행에서 4~8개. 구간 사이는 `PLAN.md` 「구간」 표, 구간 안은 「무엇부터」. 사슬(`29→30→31` 꼴)은 앞쪽에 | 번호 목록 |
| 4 | **번호를 예약한다**(`CLAUDE.md` 「병렬 줄」) — 새 `V` 가 필요한 행에 번호를 적고, 줄이 둘이면 청크 번호 대역을 줄마다 뗀다. 「최대+1」로 안 딴다 | 행의 `V` 번호, 「현재 상태」의 대역 |
| 5 | **가정을 지운다** — 행이 기대는 가정(「이 사람이 이 화면을 본다」·「이 로그가 이렇게 찍힌다」)을 뽑아 코드 읽기·로컬 실험으로 확인한다. 지운 것은 사실로 올린다. **묻기 전에 한다** — 가정이 틀리면 갈림 자체가 바뀐다 | 행의 「사실」·「불확실」 |
| 6 | 행마다 갈림을 뽑는다. 사실을 먼저 적고 갈리는 자리를 (가)/(나) 로 낸다. 선택지마다 득실과 확장성 있는 쪽을 같이 | **사용자에게 한 번에 묻는다.** 행마다 안 묻는다 |
| 7 | 답을 행에 박는다 | 아래 「행 형식」 |
| 8 | 설치가 필요한 행을 골라낸다(k6·Playwright·Grafana 같은 것). **새 `V*` 행이 하나라도 있으면 Docker Desktop 도 목록에** | 번들 표의 「설치」 칸. 실행 전에 사용자가 `!` 로 깐다 |
| 9 | 마이그레이션·설정 파일을 고치라는 행은 그 파일이 이미 배포됐나 본다 | 배포된 `V*` 는 못 고친다(`migration-immutable.sh`). 새 번호로 적는다 |
| 10 | 「구간 > 번들」 표에 한 줄 — 순서·줄·설계 날짜·설치·상태. **설명 모드(`.claude/explain-mode`)가 켜져 있으면 그 번들에서 어떻게 할지(첫 행만 펴기·끄기)를 「설계」 칸에 적는다** — 실행 세션은 그대로 따른다. 커밋한다 — `docs: 설계 — …` | 문서 청크 하나로 센다 |

## 행 형식

미착수 행의 넷(축·강제 지점·건드리는 자리·닫힘)에 넷이 는다. **`doc-lint.sh` 의 설계 행 검사가 잰다**(`Q218`) —
「번호 절차」가 있는 안 닫힌 행에 결정·불확실·실패 사다리가 없거나 닫힘이 번호를 안 가리키면 빨갛다. 「불확실」은 `Q259` 가 더했다 — 「없다」도 적어야 지나간다.

| 칸 | 무엇 | 예 |
|---|---|---|
| **사실** | 지금 코드·문서가 무엇이라 하나. 결정의 근거 — 실측한 수와 파일:줄까지. **확인한 것만 적는다** — 추정은 아래 칸 | 「`@ResponseStatus(CREATED)` 넷이 `Location` 없이 201」 |
| **불확실** | 절차 5 에서 못 지운 가정 — 운영 배포 뒤에야 보이는 값·권한·외부 서비스. 가정마다 **확인하는 법**과 **틀리면 갈 곳**(실패 사다리의 그 줄). 없으면 「없다」 | 「백엔드 운영 로그가 `trusted` 로 찍힌다 — 배포 뒤 `get-logs` 로, 다르면 `key_class` 로 판정」 |
| **결정** | 누가 언제 무엇을 골랐나 | 「2026-09-25 사용자 (가)」·「2026-09-25, 설계」 |
| **번호 절차** | ①~⑦, 파일 단위. 마지막은 시험 | 「① `V120__x.sql` ② `XQuery` ③ 시험 — …」 |
| 축·강제 지점·건드리는 자리 | 그대로 | |
| **닫힘** | 절차의 시험 번호 | 「⑤」·「③ 초록 + 부순 증거」 |
| **실패 사다리** | 절차가 안 풀릴 때 실행이 멈추지 않고 갈 길 | 「`pg_trgm` 이 운영에 없으면 인덱스를 접고 `D21` 에 적는다」 |

**절차 3~7단계가 청크 하나다.** 8 이상이면 행을 둘로 나눈다. 레인은 하나 — API 와 화면은 행이 다르다.
**게이트를 세우는 행은 부수는 단계를 절차에 넣는다**(`D25`) — 닫힘이 「초록」만이면 아무것도 안 막는 게이트가 닫힌다.

## 실행 세션이 이 행을 어떻게 쓰나

`CLAUDE.md` 「재개 프로토콜 > 번들 모드」가 든다. 요지만:

- **「불확실」을 ① 앞에 확인한다.** 그 자리에서 못 재는 것(배포 뒤 값)은 그 단계에 닿았을 때. 틀리면 적힌 갈 곳으로 가고 행에 적는다
- 행대로 간다. 행과 다르게 가면 **그 행에 적고 계속**
- 행에 없는 갈림 → 실패 사다리에 있으면 그대로. 없으면 정하고 이력에 「정한 것(계획 밖)」. **행당 둘까지** — 셋째부터는 `wip/<청크>` 가지로 빼고 다음 행
- 번들 끝 보고(`/wrapup`)가 계획 밖 결정·WIP·신규 행을 모아 사용자에게 낸다

## 설계가 못 하는 것

행이 아무리 자세해도 실행 중 드러나는 것은 남는다. 번들 A 는 여덟 중 넷이, 2026-09-25 의 도구 번들은
앞 넷(`Q215`~`Q218`)이 다 행과 다르게 갔다(`verify-fingerprint.sh` 를 대조 줄에서 못 뺀 것, 해시 빈 칸을 날짜로 가른 것 등).
**설계는 멈춤을 없애는 것이지 다름을 없애는 것이 아니다.**

**다만 확인 안 한 가정을 사실로 적은 다름은 없앨 수 있다.** 번들 8(2026-10-11)이 행과 다르게 간 셋 중 둘이 그것이었다 —
「셀러 멤버로 주문 상세를 부른다」(대표는 주문 상세를 못 본다)·「로그가 `trusted` 로 찍힌다」(톰캣이 믿은 헤더를 지워 `absent`).
둘 다 코드 한 번 읽기로 지워졌을 것이다. 그래서 절차 5 와 「불확실」 칸이 섰다.
