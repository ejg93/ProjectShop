# 예열

**세션을 여는 절차다.** 코드를 안 건드리고, 아래 넷을 하고 멈춘다.
언제 하는지는 `CLAUDE.md` 「예열」이 정한다.

1. **규칙의 뼈대를 훑는다** — `doc/reference/coding-rules.md` 의 「규칙의 우선순위」와
   「법·규정에서 온 것」. **이 두 절만** 읽는다. 통짜로 안 읽는다
2. **「현재 상태」는 세션이 열릴 때 hook 이 넣어 준다**(`2q`) — 진행중 청크·다음 청크·열려 있는 것.
   컴팩션 뒤에도 다시 들어온다. `PROGRESS.md` 를 다시 안 읽는다
3. **주간 리포트가 붙어 있으면 읽는다**(`2h`). 주 1회 같은 hook 이 「현재 상태」 뒤에 붙인다 —
   **오래 안 본 점검 줄**이 맨 위고, 그것이 다음 점검의 차례다.
   **붙어 있을 때만이다** — 없으면 이번 주에 이미 읽었다는 뜻이라 그냥 넘어간다
4. **다음 청크에 걸리는 축을 골라서 말한다.** 아래 「축을 고른다」

**펼 수 있는 것을 매번 다 펴지 않는다.** 그것이 예열의 요지다 — 전부 훑는 것은 비싸서 안 지켜지고,
**안 지켜지는 규칙은 없는 규칙**이다. 2026-08-20 재점검이 그것을 확인했다:
예열을 하고 작업한 3일치에서 서른둘이 나왔고, 그중 표준 여덟과 관례 셋은 **읽었는데 안 걸린** 것이다.

## 축을 고른다

청크 성격이 축을 정한다. **고른 것을 작업 전에 말하고 들어간다** — 말해 두면 그 청크 안에서는 걸린다.

**둘을 같이 고른다** — **무엇이 시킨 것인지**(출처)와 **어디서 막을 것인지**(강제 지점)다.
`/inspection` 「축이 둘이다」의 가로와 세로가 그 둘이고,
예열은 그중 **오늘 쓸 칸**을 고르는 것이다.

| 청크가 무엇을 건드리나 | 펴는 출처 | 내릴 강제 지점 |
|---|---|---|
| 소비자에게 보이는 값·문구·기한 | **법**(`D2` 의 요건 번호부터) | 제약. 못 내리면 테스트 |
| 응답 계약·헤더·상태 코드 | **표준·규격**(RFC·W3C 원문. 기억으로 안 쓴다) | 타입·테스트 |
| 스키마·마이그레이션 | 그 컬럼을 시킨 출처 | **제약** — 막을 수 있는 가장 낮은 자리 |
| 화면 | **화면 규약**(`D20`)과 **접근성 표준**(WCAG) | `lint`(접근성 규칙이 들었다) |
| 새 라이브러리·프레임워크 기본값 | **업계 관례**(따르든 버리든 근거를 적는다) | 설정·문서 |
| 코드를 쓰는 모든 청크 | **`D22`·`D23`** — 이건 고르는 것이 아니라 늘 걸린다 | |

**축이 둘 이상 걸리면 그것도 말한다.** 오늘 어느 자리에서 무엇이 부딪칠지가 그때 보인다.

**리포트가 붙은 주에는 그것이 입력이다**(`2h`) — 「오늘 어느 축을 보나」가 기억이 아니라
**오래 안 본 줄**에서 나온다. 실제로 세운 날 바로 「한 번도 안 봤다」 셋을 짚었고 그중 하나가 `점검 K` 가 됐다.

## 예열이 못 하는 것

**기억은 하루를 못 간다.** 예열이 축을 골라 줘도 청크가 길어지면 흐려진다 —
`14c` 가 뷰를 빠뜨렸을 때 잡은 것은 예열이 아니라 **하루 전에 세운 컬럼 대조 테스트**였고,
`11-6` 이 같은 함정을 이력에 적어 둔 것은 **재발을 못 막았다.**

그래서 예열의 결론은 언제나 하나로 이어진다 — **기억에 맡길 것을 강제 지점으로 내린다**(`D23` 축 2).
「다음에 조심한다」로 끝나는 예열은 안 한 것과 같다.
