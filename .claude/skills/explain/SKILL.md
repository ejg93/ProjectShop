# 설명

**청크를 치기 전에 구조를 펴는 층이다.** 시작 세 줄(`CLAUDE.md` 「시작 — 세 줄을 말하고 들어간다」)은
**이미 구조를 아는 사람**의 표기다 — 「`R21` — 약정은 고지가 성립 요건인데 값만 있고 화면이 없다」를
읽으려면 `D2` 요건표와 화면 계층을 이미 알아야 한다. 이 스킬이 그 앞에 **모르는 사람이 읽을 수 있는
층**을 하나 깐다.

**코드를 안 건드린다.** 설명을 펴고 멈추는 데까지가 이 스킬이다.

## 무엇으로 켜고 끄나

| 입력 | 무엇을 하나 |
|---|---|
| `/explain on` | 상태 파일 `.claude/explain-mode` 를 만든다. **그 뒤 모든 청크**가 설명을 먼저 편다 |
| `/explain off` | 그 파일을 지운다 |
| `/explain` | 지금 모드가 켜져 있나를 답한다 |
| `/explain <청크번호>` | **모드와 무관하게** 그 청크 하나를 편다. 예: `/explain 2e-6` |

**상태를 파일에 둔다.** 대화 기억에 두면 컴팩션에서 날아가고, 이 저장소는 세션이 끊기는 것을
전제로 만들었다(`CLAUDE.md` 머리말). `.claude/explain-mode` 는 커밋하지 않는다 — 사람마다,
날마다 갈리는 값이라 저장소가 들 것이 아니다(`.gitignore` 에 있다).

**모드가 켜져 있는지는 청크를 잡을 때마다 본다.** 「재개 프로토콜」 6번(작업은 「청크 하나를
어떻게 치나」를 따른다)에 들어가기 직전이 그 자리다.

```bash
test -f .claude/explain-mode && echo on || echo off
```

## 켜져 있을 때 무엇이 달라지나

**시작 세 줄을 대체하는 것이 아니라 그 앞에 붙는다.** 순서가 이렇다.

```
1. 설명을 편다  ← 이 스킬
2. 멈춘다       ← 사용자가 "가" 라고 해야 다음으로 간다
3. 시작 세 줄   ← CLAUDE.md 「시작 — 세 줄을 말하고 들어간다」
4. 코드
```

**2번이 이 스킬의 값이다.** 설명만 펴고 바로 치면 **읽고 나서 방향을 틀 자리가 없다** —
이미 쳤기 때문이다. 멈추는 자리를 만드는 것이 목적이고, 설명은 그 자리에서 무엇을 보고
판단할지를 주는 것이다.

**「가」를 기다린다.** 무엇이 오든 셋 중 하나로 읽는다.

| 사용자가 | 무엇을 하나 |
|---|---|
| 「가」·「진행」·「ㅇㅇ」 따위 | 시작 세 줄을 말하고 코드로 간다 |
| 「2번으로」 따위 | 그 선택지로 정하고 시작 세 줄로 간다 |
| 질문·「다시」 | 답하고 **다시 멈춘다.** 답했다고 진행하지 않는다 |

## 무엇을 펴나 — 다섯

**순서를 지킨다.** 아래가 모르는 사람이 읽는 순서다 — 무엇인지(1) 왜 하는지(2)
지금 어떤지(3) 뭐가 달라지는지(4) 고를 것이 있는지(5).

### 1. 청크가 무엇인가

번호·제목·**한 문장 목적**. 제목은 분할표 행에서 그대로 가져온다.

```
청크 4d — 주문 응답에서 결제 정보를 가린다
목적: 같은 주문을 봐도 사는 사람은 결제 수단이 보이고 셀러는 안 보이게 한다
```

### 2. 왜 지금 이것인가

**무엇이 시켜서 하는 것인지**를 한 줄로 댄다. 출처 넷(법·표준·규약·관례) 중 어느 것인지와,
안 하면 무슨 일이 나는지를 같이 적는다 — `coding-rules.md` 「규칙의 우선순위」의 축 1이 그 목록이다.

**「관례라서」로 끝내지 않는다.** 관례는 4순위라 근거를 대면 버릴 수 있는 것이고,
버릴 수 있는 것을 왜 지금 하는지가 설명의 핵심이다.

### 3. 지금 구조

**그림으로 그린다.** 아래 「그림을 어떻게 그리나」를 따른다. 그림에 **문제가 있는 자리를
표시한다** — 그것이 이 청크가 손댈 곳이다.

### 4. 바꾼 뒤 구조

**같은 그림을 다시 그린다.** 모양이 같아야 **무엇이 달라졌는지가 눈에 띈다** — 배치를 바꾸면
사람이 두 그림을 대조하는 데 힘을 쓰고, 정작 바뀐 한 줄을 놓친다.

**달라진 것을 그림 아래 한 줄로 짚는다.** 그림만 두 개 던지면 못 찾는다.

### 5. 고를 것이 있으면 각각의 구조

**선택지마다 그림이 하나씩 붙는다.** 「1번은 간단하고 2번은 확장성이 좋다」 같은 말로 끝내지 않는다 —
**그 말이 구조로 무엇을 뜻하는지**가 안 보이면 고를 수가 없다.

선택지를 낼 때 **확장성 있는 쪽을 반드시 후보에 넣고**, 득실을 먼저 말한다.
`CLAUDE.md` 「대전제」 1번(공부이면서 실물이다)이 그 이유다.

**고를 것이 없으면 이 항목을 안 쓴다.** 없는데 억지로 만들지 않는다.

## 그림을 어떻게 그리나

**ASCII 박스로 그린다.** 터미널에 그대로 보이는 것이 기준이다 — mermaid 는 이 창에서
소스로만 뜨고, 렌더를 보려면 창을 옮겨야 한다.

### 무엇을 그리나가 청크 성격으로 갈린다

| 청크가 건드리는 것 | 무엇을 그리나 |
|---|---|
| 컨트롤러·서비스·`*Query` | **요청이 지나는 길**. 브라우저 → 컨트롤러 → 서비스 → 표 |
| 마이그레이션·스키마 | **표와 표 사이의 관계**. 컬럼은 이 청크가 건드리는 것만 |
| record·응답 계약 | **무엇이 실려 나가나**. 칸 목록과 누가 보나 |
| 화면 | **화면과 그 위의 데이터**. 어느 칸이 어디서 오나 |
| 상태·흐름 | **전이도**. 누가 옮기는지를 화살표 옆에 |
| 빌드·검증·훅 | **언제 무엇이 도나**. 시간 순서로 왼쪽에서 오른쪽 |

### 크기를 지킨다

**상자 다섯·화살표 일곱을 넘기지 않는다.** 넘으면 그리는 범위가 틀린 것이다 —
청크가 건드리는 자리만 그린다. 주변을 다 그리면 **바뀌는 한 줄이 배경에 묻힌다.**

### 예 — 요청이 지나는 길

```
지금
  브라우저 ──POST /api/orders──▶ OrderController
                                      │
                                      ▼
                                 OrderService ──▶ order 표
                                      │
                                      └─▶ 그대로 반환  ⚠ payment 컬럼이 같이 나간다

바꾼 뒤
  브라우저 ──POST /api/orders──▶ OrderController
                                      │
                                      ▼
                                 OrderService ──▶ order 표
                                      │
                                      └─▶ OrderResponse ──▶ 반환
                                          (payment 칸이 아예 없다)

달라진 것: 표의 행을 그대로 내보내던 자리에 record 가 하나 끼었다.
```

### 예 — 표와 표 사이

```
지금                          바꾼 뒤
  order                         order
    id                            id
    buyer_id                      buyer_id
    seller_id  ⚠ 한 주문에         │
               셀러가 하나다       └──▶ seller_order
                                          id
                                          order_id
                                          seller_id

달라진 것: 셀러가 여럿인 주문을 담을 자리가 생겼다.
```

### 기호를 섞어 쓰지 않는다

| 기호 | 뜻 |
|---|---|
| `──▶` | 부른다·흘러간다 |
| `⚠` | 이 청크가 손댈 자리 |
| `│ └─` | 갈라진다 |
| `(괄호)` | 그 상자에 대한 설명 |

**`⚠` 는 「지금 구조」에만 찍는다.** 「바꾼 뒤」에 남아 있으면 안 고쳤다는 뜻이다.

## 어디서 사실을 가져오나

**분할표 행이 입력이다.** 미착수 행마다 축·강제 지점·건드리는 자리·닫힘이 이미 적혀 있다(`2t`).
설명의 1·2·5는 거의 그 행에서 나온다.

**3·4(구조 그림)는 행에 없다.** 실제 파일을 봐야 한다. 다만 **통짜로 읽지 않는다** —
행의 「건드리는 자리」 칸이 파일 이름을 적어 뒀고, 그 파일들만 연다.

**모르는 것은 모른다고 적는다.** 지금 구조를 확인 안 하고 그린 그림은 **틀린 지도**라
안 그린 것보다 나쁘다 — 사용자가 그것을 믿고 「가」라고 한다.

## 이 스킬이 못 하는 것

**설명이 정확하다는 보장은 이 스킬에 없다.** 그림은 강제 지점 5위(문서)라 아무것도 안 막는다 —
틀려도 빌드가 초록이고 테스트도 통과한다.

그래서 **설명과 코드가 갈리면 코드가 맞다.** 청크를 치다가 그림과 다른 것을 보면
그 자리에서 밝히고, 「지금 구조」를 잘못 그렸던 것이면 **왜 잘못 봤는지**를 이력에 적는다 —
다음에 같은 자리에서 또 그렇게 본다.
