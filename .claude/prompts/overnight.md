# 밤 번들 — 자는 동안 무인으로 번들을 잇는 프롬프트

설계 행(`/design`)이 이미 적힌 번들을 **사람 없이 여러 개 연달아** 칠 때의 여는 말이다. `bundle-session.md` 와 다르다 —
그쪽은 계획을 이 세션에서 세우고 계획 밖 갈림에서 멈추지만, 이쪽은 계획이 이미 있어 **멈추는 자리가 토큰 창과 CI 뿐**이다.
ProjectTicket 세션이 같은 목적으로 정한 방식(2026-09-26)을 이곳 이름으로 옮겼다.

**규칙 본문은 여기 없다.** `CLAUDE.md` 「재개 프로토콜 > 번들 모드」·`/wrapup`·`/verify` 가 든다. 여기 있는 것은 **밤에만 다른 것**뿐이다.

## 자기 전에 사람이 하는 것

| 무엇 | 왜 |
|---|---|
| 플러그를 꽂고 뚜껑을 연다 | 절전이 AC 는 없고 배터리는 3분이다(`powercfg`). 잠들면 세션이 그 자리에서 선다 |
| `/model` 로 실행 모델(Opus)을 고른다 | 설계는 Fable, 실행은 Opus(`/design`) |
| 아래 블록을 붙여넣고 마지막 줄의 토큰 비율을 채운다 | 안 적으면 규칙상 청크 하나만 치고 멈춘다 |

**토큰 5시간 창이 다 차면 세션이 서고 스스로 다시 시작하지 않는다.** 청크 하나 = 커밋 하나라 선 자리는 깨끗하다 —
아침에 「번들 해」 한마디가 「현재 상태」·이력 마지막 줄에서 잇는다. 페이스 실측은 8행 + 마무리 ≈ 2시간 10분(ProjectTicket, Opus)이다.

## 붙여넣는 것

```
/warmup

예열 끝나면 밤 번들이다. PLAN.md 「구간 > 번들」 표에서 상태 칸에 「밤 <오늘 날짜>」가 적힌 번들을
표의 순서대로 친다. 규칙은 CLAUDE.md 「번들 모드」다 — 여기서는 밤에만 다른 것을 적는다.

[먼저 확인]
1. bash scripts/docker-up.sh — Docker 가 꺼져 있으면 켠다. 3분 안에 안 뜨면 거기서 멈추고 보고한다.
2. git status 가 깨끗하고 가지가 work/* 인지. 아니면 멈추고 보고한다.
3. 설명 모드(.claude/explain-mode)가 있으면 지운다 — 번들 표 「설계」 칸이 「끈다」고 적었다.

[청크마다]
- 그 행만 읽는다. 시작 세 줄은 행에 있으니 확인만 한다.
- 번호 절차대로. 계획 밖 갈림은 실패 사다리 → 없으면 정하고 이력에 「정한 것(계획 밖)」.
  행당 둘까지. 셋째면 wip/<청크> 곁가지에 커밋하고 다음 행.
- bash scripts/verify.sh 가 빨가면 고치기 둘까지. 그래도면 wip/<청크> 로 빼고 다음 행.
- 커밋 하나. 새 게이트면 scripts/probes/<이름>.patch 를 남기고 커밋 뒤 bash scripts/gate-probe.sh <이름> 결과를 이력에(Q225).
- PLAN 행 완료 형식 + 번들 표 「k/n」, PROGRESS 이력 한 줄(직전 행 해시를 이름으로 찾아 채운다).
- 청크 사이에 턴을 안 끝낸다. 보고는 한 줄이다.

[번들 끝 — /wrapup 그대로, 여기서만 더하는 것]
- 독립 리뷰의 지적은 전부 지금 고치거나 새 행으로. 오탐은 근거를 적는다.
- bash scripts/verify.sh --full 은 push 와 따로 낸다.
- push → gh pr create --base main(청크마다 시작 세 줄 표) → CI 를 gh api 로 폴링한다.
- **머지를 맡겼다**: CI 전부 초록이고 리뷰 봇 코멘트를 처분했으면 gh pr merge N --merge →
  bash scripts/deploy-check.sh → git checkout main && git pull → 다음 가지 work/<날짜>-N.
- CI 빨강은 고치기 둘까지. 그래도면 PR 을 열어 둔 채 멈추고 보고한다.
- deploy-check 가 빨가면 다음 번들보다 먼저 본다. 못 고치면 멈추고 보고한다.

[멈추는 자리 — 여기서만 멈춘다]
- 번들 표의 밤 번들을 다 쳤다.
- 토큰이 20% 밑이다 — 진행중 청크가 있으면 wip/ 로 빼고 /wrapup 까지 한다.
- CI·deploy-check 를 두 번 못 고쳤다.
- 행이 사람의 입력(주소·설치·GitHub 설정 변경)을 요구한다 — 그 행은 접고 다음 행. 번들에 그런 행만 남으면 멈춘다.

[끝 보고 — 멈출 때]
PROGRESS 이력 마지막 줄 + 「현재 상태」 + 마지막 PR 본문에: 계획 밖 결정 전부 · wip/ 로 뺀 행과 이유 ·
새로 선 행 · 사람이 할 것. 아침에 볼 것 셋: main 마지막 커밋, gh pr list, git branch --list 'wip/*'.

토큰은 이번 5시간 창에 __% 남았다.
```

## 조항마다 무엇을 막나

| 조항 | 빼면 |
|---|---|
| `docker-up.sh` 를 맨 앞에 | 안 떠도 `verify.sh` 가 Windows 에서 스스로 켠다(`Q232`) — 맨 앞에 두는 것은 첫 `--full` 에서 3분을 안 기다리고, 안 뜨는 판을 청크 전에 알기 위해서다 |
| 설명 모드를 지운다 | 켜 둔 채면 청크마다 구조를 펴고 멈춘다(`/explain`) |
| 계획 밖 갈림은 정하고 간다 | `bundle-session.md` 의 「멈추고 묻는다」가 밤에는 곧 정지다. 설계 세션이 이미 물었다 |
| `wip/<청크>` 로 뺀다 | 빨간 트리가 `work/*` 에 오르면 commit hook 이 막고 뒤 청크가 다 빨개진다(`Q215`) |
| 머지 위임을 글로 적는다 | 안 적으면 마무리가 PR 을 열고 멈춘다. 둘째 번들이 첫 PR 위에 쌓여 리뷰 diff 가 커진다 |
| CI 는 `gh api` 로 폴링 | `gh pr checks` 는 권한 분류기가 막고 폴링이 조용히 헛돈다 |
| 사람 입력이 필요한 행은 접는다 | `Q209` 주소·`Q112` ruleset 같은 자리에서 밤새 기다린다 |
| 토큰 20% 에서 마무리 | 창이 차면 마무리 없이 선다 — 아침에 PR 없는 커밋 열 개를 사람이 정리한다 |
| 끝 보고 셋 | 아침에 무엇이 어디까지 됐는지 세 명령으로 안 보이면 「현재 상태」를 다시 읽어야 한다 |
