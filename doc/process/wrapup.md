# 마무리

**이 세션에서 친 청크를 한꺼번에 정리하는 절차다.** 언제 여는지와 「드러난 것의 처분」과
어떻게 짝인지는 `CLAUDE.md` 「마무리」가 정한다.

하는 일이 셋이다.

| 무엇 | 무엇을 남기나 |
|---|---|
| **더할 청크를 찾는다** | 이번에 드러났는데 어느 청크도 안 다루는 것 → `PLAN.md` 에 행 |
| **고칠 것을 찾는다** | 아래 표의 일곱 대조. 규모에 따라 지금 고치거나 청크로 |
| **한 일을 적는다** | `PROGRESS.md` 이력에 한 줄. 무엇을 왜 그렇게 정했는지 |

**횟수를 안 정한다.** 한 세션에서 여러 번 해도 되고, 그때마다 **직전까지 친 청크**가 대상이다 —
`1차 마무리`·`마무리 (2)` 처럼 이력에 회차를 적는다. **세션이 길면 중간에 하는 편이 낫다**:
청크가 쌓일수록 「결정끼리 부딪치나」를 볼 때 다시 읽을 것이 늘어난다.

**대상은 그때까지 친 청크 전부다.** 마지막 청크만 정리하는 것이 아니다 —
**먼저 커밋을 훑어 청크를 세고**, 그것들이 `PLAN.md` 와 `PROGRESS.md` 에 다 닫혔는지부터 본다.
그다음이 아래 표다. 안 건드린 자리도 표의 대조에는 걸린다(문서가 부르는 것은 저장소 전체다).

위 「처분」이 **나온 자리에서 적는 것**이라면, 마무리는 **그 처분이 실제로 됐는지 확인하는 것**이다.
둘이 짝이고, 마무리가 없으면 처분은 적힌 채로 안 밟힌다.

고치는 것은 **지금 규칙으로 읽히는 글**뿐이다. **이력은 그때의 사실이라 안 고친다** —
`V8` 이 지워졌어도 「그때 `V8` 을 고쳤다」는 이력은 맞는 말이다.

**아래 표를 손으로 보기 전에 `bash scripts/doc-lint.sh` 부터 돌린다.** 제목 파편·완전
중복 문장처럼 기계가 잡는 것을 사람이 또 훑을 이유가 없다. 아래 일곱은 기계가 못 잡는 것만 남는다.

| 무엇을 보나 | 어떻게 |
|---|---|
| 문서가 부르는 것이 있나 | `V번호`·클래스·테스트 이름이 실물과 맞나 |
| 끝난 청크가 분할표에 있나 | 이력에만 있고 `PLAN.md` 에 없는 청크 |
| 미룬 것이 청크에 실렸나 | 「나중에」·「그때」로 끝난 문장에 **어느 청크인지** 적혔나 |
| 가리키는 청크가 있나 | 처분이 **계획에 없는 청크**를 가리키지 않나 |
| 결정이 코드와 같나 | 문서가 고른 값과 설정·상수가 어긋나지 않나 |
| **이번 결정끼리 부딪치나** | 청크 A 가 정한 것을 청크 B 가 어기지 않나. **참조·값 대조로는 안 걸린다** |
| **말한 축과 편 축이 같나** | 시작 세 줄에서 「법을 편다」고 해 놓고 조문을 안 봤거나, 「제약으로 내린다」고 해 놓고 테스트로 끝냈나 |

앞의 다섯은 2026-08-20 에 다 걸린 적이 있다 — 삭제된 `V8` 을 가리키던 요건표,
이력에만 있던 `D23-1`, 본문에만 적혀 있던 미룬 것 넷, **계획에 없는 청크**를 가리키던
카드번호 처분, `stack.md` 가 버린 선택을 켜 둔 설정.

**일곱째는 2026-08-23 에 들어왔다.** `12a-5` 가 시작 세 줄에서 「기한 넘긴 대기를 **회차에** 남긴다」고
해 놓고 로그로 갔는데, **그 자리에서 안 밝혔다.** 마무리가 우연히 봤지 대조 항목이 아니었다 —
**예열이 축을 고르고 청크가 다시 고르는 구조라, 「고른 것을 실제로 폈나」를 보는 자리가 필요하다.**

**여섯째가 그전까지 제일 늦게 들어온 것이었다**(2026-08-22, 사용자 지적). 앞의 다섯은 **글과 실물**을 맞추는 것이라
`grep` 으로 돌지만, 이것은 **결정과 결정**을 맞추는 것이라 하루 치 결정을 다시 읽어야 나온다.
그날 셋이 걸렸다 — `create` 에만 넣고 `replace` 에 안 넣은 저장, 배치와 관문이 **다른 동의 항목**을 본 것,
채널이 없는데 **확인 통지가 나가던 것**. **셋 다 테스트도 빌드도 초록이었다.**

## 찾은 것을 어떻게 처분하나

**「드러난 것의 처분」과 다른 표다.** 그쪽은 **청크를 하다** 나온 것이고 이것은 **마무리에서** 나온 것이다 —
앞은 「어느 청크가 볼 것인가」를 정하고, 여기는 **「지금 고칠 수 있나」**를 정한다.

**그 자리에서 고치는 것이 기본이다.** 마무리에서 나온 것을 또 미루면 마무리가 두 번 필요해진다.
다만 **규모가 그것을 못 하게 하는 것**이 있어서, 셋 중 하나로 가른다.

| 규모 | 어떻게 | 예 |
|---|---|---|
| 글 한 줄·값 하나·빠뜨린 호출 | **지금 고친다** | 없어진 청크를 가리키는 참조, `replace` 가 빠뜨린 저장 |
| 이미 있는 청크가 다룰 것 | **그 행에 적는다** | 정산이 지연배상금을 셀러 몫에서 빼면 안 된다(`19` 행) |
| 설계 결정이 필요하거나 파일이 여럿 | **새 청크를 세운다** | 파기가 셀러 행동에 매달린 것(`10a-2`) |

**가르는 기준은 「지금 고치면 마무리가 안 끝나나」**다. 고치는 데 결정이 필요하면 그건 청크다 —
마무리 안에서 임의로 정하면 **그 결정이 아무 데도 안 적힌 채로 코드에 들어간다.**

**어느 쪽으로 갔든 이력에 밝힌다.** 안 고치고 남긴 것은 **왜 남겼는지**까지 적는다.
