# 문서 트리

문서를 종류별로 갈라 두고, 새 문서가 생길 때 어디에 놓을지를 이 파일 하나로 판단한다.

## 어디에 무엇이 있나

| 경로 | 무엇이 들어 있나 | 누가 읽나 |
|---|---|---|
| `doc/reference/` | 여러 청크가 같이 참조하는 기준 문서(D1~D21) | 그 결정에 걸린 청크를 잡은 사람 |
| `doc/adr/` | 한 번 정하고 되돌릴 때 근거가 필요한 결정 | 그 결정을 뒤집으려는 사람 |
| `doc/notes/` | 읽을거리. **청크 실행 때 안 본다** | 읽고 싶은 사람 |
| `PLAN.md` | 만들 대상과 청크 분할표 | 다음 청크를 고르는 사람 |
| `PROGRESS.md` | 청크별 완료·진행중 로그 | 세션을 재개하는 사람 |
| `README.md`(저장소 루트) | 띄우는 법과 돌리는 명령 | 처음 받은 사람 |

## 기준 문서와 ADR 을 가르는 기준

**참조자가 몇인가로 가른다.**

| 참조하는 청크 | 어디에 | 왜 |
|---|---|---|
| 둘 이상 | `doc/reference/` | 청크마다 다시 정하면 서로 어긋난다 |
| 하나 | `doc/adr/` | 기준 문서에 넣으면 안 읽어도 될 사람이 읽는다 |

한 청크에서만 쓰는 결정이라도 **나중에 "왜 이렇게 했나" 를 물을 것 같으면** ADR 로 남긴다.
근거 없이 남은 코드는 다음 사람이 무심코 뒤집는다.

`doc/notes/` 는 둘 중 어느 쪽도 아니다. **결정이 아니라서** 여기 있다.
청크를 잡을 때 이 폴더를 읽지 않고, 여기 적힌 것을 근거로 코드를 쓰지 않는다.

## 파일명

- 영문 kebab-case. 한글 파일명은 경로 인용과 셸 조작이 번거롭다
- 기준 문서는 내용을 그대로 쓴다 — `money-rules.md`, `data-lifecycle.md`
- ADR 은 `NNNN-슬러그.md`. 번호는 4자리 연번이고 비워 두지 않는다 — `0009-holiday-and-transition-table.md`
- 문서 번호(D1·D2)는 파일명에 안 넣는다. 번호는 `PLAN.md` 의 표에서만 쓰고,
  파일명에 박으면 번호를 바꿀 때 링크가 전부 깨진다

## 고치는 방식

| 종류 | 방식 |
|---|---|
| 기준 문서 | 덮어쓴다. 지금 유효한 결정만 남는다 |
| ADR | **안 고친다.** 뒤집으려면 새 ADR 을 쓰고 옛 ADR 에 뒤집혔다고 한 줄 단다 |

기준 문서는 "지금 무엇이 맞나" 를 답하고 ADR 은 "그때 왜 그랬나" 를 답한다.
ADR 을 덮어쓰면 뒤의 질문에 답할 것이 사라진다.

## 문서에 안 쓰는 것

코드가 답하는 것은 안 쓴다. 코드는 바뀌고 문서는 안 따라와서 문서 쪽이 거짓말이 된다.

| 안 쓴다 | 어디서 답하나 |
|---|---|
| 클래스·테이블 구조, 컬럼 목록 | 마이그레이션 파일, 엔티티 |
| 무엇이 무엇을 호출하나 | 코드 검색 |
| API 요청·응답 형식 | springdoc 이 뽑는 `/api/docs`(청크 2a) |
| 지나간 작업 이력 | `PROGRESS.md`, git log |

문서에 쓰는 것은 **코드를 봐도 안 나오는 것**이다. 왜 그 구조를 골랐나, 무엇을 안 하기로 했나,
어긋나면 무엇이 깨지나.

## 글 쓰는 규칙

`CLAUDE.md` 의 「글 작성 규칙」을 따른다. 여기에 다시 적지 않는다.
