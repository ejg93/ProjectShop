# 0003. 스코프는 role_permission 행에 둔다

- 날짜: 2026-08-03
- 상태: 채택

## 결정

행 단위 조건(`own` / `seller` / `all`)을 `role_permission.scope` 컬럼에 둔다.
`(role_id, permission_id)` 가 기본키라서 한 역할은 같은 권한을 스코프 하나로만 갖는다.

## 저울질한 것

| 후보 | 왜 안 골랐나 |
|---|---|
| `permission` 에 스코프를 붙인다 | `order:read:own` 과 `order:read:all` 이 다른 권한이 된다. 권한 개수가 스코프 배수로 늘고, "주문 조회 권한이 있나" 를 물을 때마다 변종을 전부 나열해야 한다 |
| 스코프를 코드에 박는다 | 판매자에게 `order:read` 를 `all` 로 열어 주는 실험이 재배포 없이는 불가능해진다. 권한을 데이터로 둔 이유가 사라진다 |
| `(role, permission)` 당 여러 스코프 허용 | 판정이 모호해진다. `own` 과 `all` 이 같이 붙으면 결국 넓은 쪽만 의미가 있어서 좁은 행은 읽히지 않는 죽은 데이터가 된다 |

## 따라오는 제약

- 한 사용자가 역할을 여럿 가지면 같은 권한이 여러 스코프로 잡힌다. 이때는 넓은 쪽이 이긴다(`all` > `seller` > `own`). 판정 엔진은 청크 4에서 이 순서를 구현한다
- 스코프 값을 늘리려면 `role_permission_scope_check` 를 바꾸는 마이그레이션이 필요하다. 자유롭게 늘릴 자리가 아니라 판정 엔진이 이해하는 값만 들어가야 한다
- `seller` 스코프는 판매자와 상품이 연결된 뒤에야 실제로 판정된다. 청크 6·7에서 이어 붙인다
