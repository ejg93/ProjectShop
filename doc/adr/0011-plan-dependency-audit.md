# 0011. 미착수 청크의 선행을 다시 훑고 D21 순환을 깬다

- 날짜: 2026-08-09
- 상태: 채택

## 결정

청크 `1`~`16` 은 `D1`~`D23` 이 하나도 없을 때 세웠다. 문서가 스물세 장 생긴 지금
분할표를 다시 유도할지가 걸려 있었다. **전면 재유도는 안 하고 미착수분의 선행·순서만 훑는다.**

전면 재유도를 접은 근거는 둘이다.

- 미착수 코드 청크 `10`·`11`·`11a`·`12`·`13`·`13a` 의 설명에 이미
  `D3`·`D7`·`D8`·`D9`·`D10`·`D11`·`D14` 참조가 붙어 있다. 재유도가 노리는 것이 대부분 들어가 있다
- 전면 규칙 점검(`checkpoint-3-rules.md`)에서 코드 구조 결함이 0 이었다

접었다고 훑을 것이 없는 것은 아니다. **순서 결함은 코드 결함과 별개로 실재한다.**
`7b` 를 `7` 앞으로, `3c` 를 상품 축 앞으로, `17-1` 을 `17` 앞으로 옮긴 세 번이 전부
**그 청크를 잡는 순간에** 발견됐다. 표를 보고 안 것이 아니라 손을 대고 나서 알았다.

## 고친 것

| 결함 | 무엇이었나 | 어떻게 |
|---|---|---|
| `17-1` 순환 | 선행에 `10` 이 있는데 본문은 "`10` 앞에 온다" | 선행을 `D3, D8` 로. `10` 의 선행에 `17-1` 을 넣는다 |
| `17-1` 위치 | 확장 청크 절에 있었다. 그 절은 "16b 이후다" 로 시작한다 | 메인 분할표의 `10` 앞으로 옮긴다. 번호는 안 바꾼다 |
| 화면 축 `D20` 누락 | `13b`·`14`·`15`·`16`·`16a`·`16b`·`13a` 가 `screen-rules.md` 완료 전에 세워졌다 | 선행에 `D20` 을 넣는다 |
| 참조 누락 | 설명 본문은 참조하는데 선행 칸이 비었다 | `2a`→`D5`, `5a`→`D6`, `12`→`D14`, `11a`→`8a`, `13a`→`9` |
| `D21` 순환 | 아래 절 | 아래 절 |
| `5j` 행이 표를 깬다 | 설명 안에 이스케이프 안 된 `\|` 가 있어서 5칸 행이었다 | 파이프를 없앤다 |

마지막 것은 렌더된 화면에서 열이 밀려 보이는데 소스로는 안 보인다.
표를 파싱해서 칸 수를 세지 않았으면 못 찾았다.

## D21 성능 목표 — 42 뒤로 보낸다

`D21` 은 선행이 `0`(없음)인데도 못 썼다. 응답 시간 기준을 정하려면 측정값이 있어야 하는데
부하를 준 적이 없어서다. 그 사이 `38`·`42`·`60`·`70` 넷이 `D21` 을 선행으로 걸고 잠겨 있었다.

**`42` 성능 측정·튜닝의 선행에서 `D21` 을 뺀다.** 실행 계획을 읽고 느린 쿼리를 찾는 데
목표 수치가 필요 없다. `42` 가 먼저 돌아 측정값을 만들고, 그 값이 `D21` 의 입력이 된다.
`D21` 의 선행은 `42` 가 된다.

`38`·`60`·`70` 은 `D21` 뒤에 그대로 둔다. 셋 다 "지금 것이 느린가" 를 알아야 시작할 값이 있다.

문서를 둘로 쪼개는 안(측정 방법·규모 가정 / 목표 수치)도 저울질했다.
넷을 동시에 푸는 대신 기준 문서가 하나 늘고 `D` 번호에 글자가 붙는다.
잠긴 넷이 전부 확장 청크라 당장 급하지 않아서 표 한 칸만 움직이는 쪽을 골랐다.

## 따라오는 것

- **`17-1` 이 다음 청크다.** 선행 `D3`·`D8` 이 둘 다 완료라 지금 잡을 수 있다
- 분할표에 번호가 자리를 안 따르는 행이 하나 생겼다(`9` → `17-1` → `10`).
  번호를 밀지 않으려고 감수했고 그 이유를 행 안에 적어 뒀다
- 선행 표기를 고칠 때 순환과 미정의 참조를 파싱으로 확인한다.
  이번에 90개 노드에서 순환 0, 미정의 0 을 확인했다
