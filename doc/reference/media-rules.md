# 파일·미디어 규약

올라온 파일을 무엇으로 받고, 어디에 두고, 누구에게 열어 주는지 정한다.

**이 문서가 값을 박고 청크 `26`~`28` 이 그것을 `check` 와 필터로 내린다.**
여기서 「나중에 정한다」로 남긴 것은 그 청크에서 각자 정하게 되고, 그러면 자리마다 값이 갈린다.

## 순환을 깨고 썼다

2026-09-18 기준으로 **업로드 코드가 0개다.** 그런데 근거를 만들 `26` 의 선행이 이 문서라
서로를 물고 있었다. `D12` 이벤트 카탈로그가 같은 모양이었고 append-only 표를 근거로 깼다.

**여기서 정할 값은 이미 있는 것에서 세어 나온다.**

| 정할 것 | 근거가 어디 있나 |
|---|---|
| 크기·형식 제한 | `security-baseline.md` 입력 검증 표 · OWASP File Upload Cheat Sheet |
| 접근 권한 | `permission-rules.md` 의 `PermissionEvaluator` — 파일도 같은 판정을 탄다 |
| 저장 경로 | 청크 `27` 이 「경로 이름은 앱이 만든 것만 쓴다」를 이미 들고 있다 |
| 개인정보 | `coding-rules.md` 「개인정보 컬럼은 셋을 같이 채운다」 |

## 받는 것 — 제한값

| 무엇 | 값 | 출처 |
|---|---|---|
| 한 파일 최대 크기 | **5 MiB** (5,242,880 바이트) | 관례 — 스마트폰 사진 한 장이 2~5 MB 다. **남의 값을 안 셌다**(아래) |
| 상품 하나당 최대 장수 | **10장** | 관례 — **남의 값을 안 셌다**(아래) |
| 후기 하나당 최대 장수 | **10장** | **상품과 같은 값이다**(사용자 결정 2026-09-23, `Q159`) — 세지 않은 값을 하나 더 만들지 않았다. 앱은 `ImagePipeline.MAX_IMAGES_PER_OWNER` 하나를 같이 쓰고, 트리거는 표마다 있다(`product_image_limit`·`review_image_limit`) |
| 허용 MIME | **`image/jpeg` · `image/png`** | OWASP(허용 목록으로 받는다) |
| 허용 확장자 | `.jpg` · `.jpeg` · `.png` | 위 MIME 과 짝인 것만 |

**두 값은 세어 본 것이 아니다**(2026-09-18 `점검 P`). `coding-rules.md` 가 관례 값을 적을 때
**남들이 얼마인지를 같이 적는 선례**를 뒀는데(「100 은 관례다(4순위). 스마트스토어 100 · Shopify 255」)
여기는 그것을 안 했다. `CLAUDE.md` 「대전제」가 **「업계 관례는 근거가 아니라 그 수를 세는 참고다」**
라고 적어 둔 그 자리다.

**지금 고쳐 쓸 근거가 없어서 그대로 두고 밝힌다** — 바깥을 봐야 나오는 수고,
안 본 채로 숫자만 바꾸면 **근거 없는 값이 근거 있는 것처럼 보인다**. 값이 걸리는 날
(셀러가 「열 장으로 모자란다」고 하거나 5 MiB 에서 막히는 사진이 나오는 날)에 세고 고친다.

**SVG 를 안 받는다.** 스크립트를 품을 수 있어서 이미지가 아니라 실행 가능한 문서다(OWASP).
**GIF 도 안 받는다** — 애니메이션은 아래 「썸네일」의 변환 규칙이 한 장을 전제하기 때문이다.
**WebP 도 안 받는다**(2026-09-18) — JDK 의 `ImageIO` 가 WebP 를 **읽지도 쓰지도 못한다.**
네이티브 라이브러리를 안 들이기로 한 결정이 받는 쪽에도 그대로 걸린다.
둘 다 필요해지면 이 문서를 먼저 고친다.

### 클라이언트가 보낸 `Content-Type` 을 안 믿는다

**내용의 앞부분(매직 바이트)으로 형식을 판별하고**, 그것이 위 허용 목록에 있는지 본다.
요청 헤더는 보내는 쪽이 자유롭게 적는 값이라 검증의 입력이 될 수 없다(OWASP).

| 검사 | 무엇을 보나 |
|---|---|
| 1 | 실제 내용의 매직 바이트 → 허용 MIME 인가 |
| 2 | 확장자 → 1에서 나온 MIME 과 짝인가(`Q96`). **이름을 검증의 입력으로 쓰는 것이 아니다** — 형식은 내용이 정했고 여기서는 이름이 그것과 다른지만 본다 |
| 3 | 바이트 수 → 5 MiB 이하인가 |

**셋이 각자 다른 코드를 낸다.** 크기와 형식은 HTTP 가 이미 뜻을 정해 둔 자리라 그 코드를 쓴다(`D5`).

| 어긋난 것 | 상태 | 슬러그 |
|---|---|---|
| 크기 | **413** | `image-too-large` |
| 형식 | **415** | `image-type-not-allowed` |
| 장수 | **422** | `image-limit-reached` (우리 규칙이라 HTTP 에 자리가 없다) |

**뭉뚱그리지 않는 이유는 화면이다.** 셋이 사용자에게 시키는 일이 다르다 — 크기는 줄여서 다시,
형식은 다른 파일로, 장수는 지우고 다시다. 하나로 묶으면 화면이 「올릴 수 없다」만 말한다.

**허용 목록의 모양이 새는 것은 감수한다.** 파일 형식 목록은 숨겨서 지키는 값이 아니다 —
이 문서에 그대로 적혀 있고, 숨겨도 두 번 시도하면 알아낸다.

### EXIF 를 지운다

사진에는 **촬영 위치와 시각**이 들어 있다. 상품 사진에 셀러의 집 좌표가 실려 나가고,
반품 검수 사진에 사는 사람의 좌표가 실린다. **개인정보라 받는 즉시 지운다.**

지우는 자리는 **저장 전**이다. 저장한 뒤에 지우면 그 사이에 원본이 저장소에 존재한 구간이 생기고,
그 구간은 파기 대상으로 셀 수가 없다(`coding-rules.md` 「수집하는 코드가 파기하는 코드보다 먼저 나오면」).

**지우는 방법은 다시 인코딩이다**(2026-09-18). 이미지를 읽어서 다시 쓰면 메타데이터가 안 따라온다 —
지울 항목을 열거하지 않아서 **새 항목이 생겨도 안 샌다.** 그래서 **저장하는 것은 받은 바이트가 아니라
다시 인코딩한 이미지**고, 형식은 받은 것과 같게 쓴다(JPEG → JPEG, PNG → PNG).

### 바이러스 검사를 안 한다

**일부러 안 넣은 것이라 근거를 적는다**(`coding-rules.md` 「안 넣은 것도 근거를 남긴다」).

로컬 전용이고 올라오는 것이 우리가 넣은 데모 데이터뿐이다. 검사기를 넣으면
**컨테이너가 하나 늘고 업로드가 그 장애를 그대로 받는다**(`D14` 「바깥을 부르면 그 장애가 우리 장애가 된다」).
**바깥 사람이 올리기 시작하면 이 결정을 다시 본다.**

## 두는 곳 — 저장 경로

**경로에 사람이 지은 이름을 안 쓴다.** 원본 파일 이름은 컬럼에만 두고, 저장소의 키는 앱이 만든다.

```
{버킷}/{자원}/{UUID}/{이름}.{확장자}

shop-public/product/0193f2c1-…/original.jpg
shop-public/product/0193f2c1-…/thumbnail.jpg
shop-private/return-inspection/0193f3a0-…/original.jpg
```

| 규칙 | 왜 |
|---|---|
| 키에 원본 이름을 안 쓴다 | 경로 탈출(`../`)과 이름 충돌이 성립하지 않는다 |
| 키에 순번을 안 쓴다 | **이 키는 서명 URL 에 그대로 실려 나간다** — 순번을 넣으면 사는 사람이 주소만 보고 상품 총량과 증가 속도를 읽는다(`identifier-rules.md` 와 같은 이유). 상품 번호도 안 넣는다 |
| 버킷을 공개로 안 만든다 | 아래 「여는 법」이 유일한 입구가 된다 |

**원본 이름·MIME·바이트 수는 컬럼으로 받고 `check` 로 좁힌다**(청크 `27`). 표시에만 쓰고
저장 위치를 정하는 데 안 쓴다.

## 여는 법 — 둘을 섞는다

**공개 여부로 가른다**(사용자 결정 2026-09-18).

| 갈래 | 어떻게 | 무엇이 여기 |
|---|---|---|
| **공개** | 앱이 판정한 뒤 **만료 5분짜리 서명 URL** 을 내주고, 브라우저가 저장소로 바로 간다 | 상품 이미지, 후기 사진 |
| **비공개** | 요청마다 앱을 지나고 **매번 판정한다**. 앱이 바이트를 나른다 | 반품 검수 사진, 손해배상 증빙 |

**가르는 기준은 「로그인 안 한 사람에게도 보이나」다.** 상품 목록은 누구나 보므로 공개고,
그 밖은 전부 비공개다. **애매하면 비공개다** — 틀렸을 때 한쪽은 느려지고 다른 쪽은 샌다.

**버킷을 갈래마다 하나씩 둔다** — `shop-public` 과 `shop-private` 다(`26`). 같은 버킷에 섞으면 키를 보고 갈래를 판단하게 되고,
그 판단이 한 번 틀리면 비공개 파일이 서명 URL 로 나간다.

### 공개 쪽도 판정을 지난다

서명 URL 은 **발급 시점에 한 번** 판정한다. 만료 5분 동안은 URL 을 아는 사람이 연다.

**그래서 만료가 짧다.** 상품 목록 한 화면을 보는 동안 유효하면 되고, 그 URL 이 남에게 넘어가도
5분 뒤에는 아무것도 아니다. **비공개 파일에 이 방식을 안 쓰는 이유가 그 5분이다.**

| | 공개(서명 URL) | 비공개(프록시) |
|---|---|---|
| 판정 횟수 | 발급 때 한 번 | 요청마다 |
| URL 이 새면 | 5분간 열린다 | 안 열린다 |
| 앱이 바이트를 나르나 | 아니다 | 그렇다 |

## 썸네일 — 업로드 때 한 장

**목록은 썸네일을 받고 상세는 원본을 받는다**(사용자 결정 2026-09-18).

| 무엇 | 값 |
|---|---|
| 긴 변 | **600 px** |
| 비율 | 원본 비율을 지킨다. 잘라내지 않는다 |
| 형식 | **JPEG** — 원본 형식과 무관하게 하나로 만든다 |

**JPEG 인 이유는 의존성이다**(2026-09-18 사용자 결정). WebP 로 쓰려면 네이티브 라이브러리가 필요한데, JDK 의 `ImageIO` 는 WebP 쓰기를 안 준다 — OS·아키텍처마다 바이너리가 갈리는 것을 들이는 값이 **파일 25~35%** 보다 비싸다. 썸네일은 600px 이라 그 차이의 절대량이 작다.

**만드는 시점은 업로드 처리 안이다.** 요청이 끝나기 전에 원본과 썸네일이 둘 다 저장된다.

### 썸네일을 못 만들면 업로드가 실패한다

**원본만 남기지 않는다.** 남기면 「썸네일이 없는 이미지」라는 상태가 생기고,
그 상태를 목록 화면이 또 다뤄야 한다 — `D20` 에 규칙이 하나 늘고, 그 규칙을 빠뜨리면 목록이 깨진다.

**실패를 한 곳에 모으는 편이 싸다.** 업로드가 통째로 400 이면 화면이 다룰 것은 이미 있는
「업로드 실패」 하나뿐이다.

## 남의 것이 올라오면

**저작권법 제102~103조가 신고·삭제 절차를 요구한다.** 그 절차가 있어야 온라인서비스제공자
책임 제한을 받는다. **요건 번호와 강제 지점은 `D2` 가 든다** — 청크 `26` 이 승격시킨다.

이 문서가 그 절차에 거는 것은 하나다: **삭제는 저장소에서 실제로 지운다.**
플래그만 세우고 파일을 두면 서명 URL 을 아는 사람에게는 계속 열린다.

## 개인정보가 담긴 파일

**반품 검수 사진처럼 사람이 찍히는 파일은 개인정보다.** 컬럼과 같은 규칙을 그대로 받는다
(`coding-rules.md` 「개인정보 컬럼은 셋을 같이 채운다」).

| 채울 곳 | 무엇을 |
|---|---|
| 동의 항목(`consent_item`) | 수집 항목에 그 파일이 있나 |
| `D13` 데이터 수명 | 보유기간이 정해졌나 |
| 파기 코드 | 그 기간이 지나면 **저장소에서도** 지우는 자리가 있나 |

**셋째가 파일에서 더 세다.** 행을 지워도 저장소의 객체는 안 사라진다 —
파기 배치가 표와 저장소를 **둘 다** 지워야 파기다.

**후기 사진은 공개 게시물로 다룬다**(사용자 결정 2026-09-23, `Q159`). 사람이 찍힐 수 있지만 쓴 사람이 스스로 공개하는 글과
같은 급이라 위 셋 중 동의 항목을 따로 안 세운다 — 남의 개인정보가 담긴 사진은 신고 사유 `privacy` 로 후기째 내린다.
**셋째(파기)는 그대로 받는다** — 후기가 보존기간 끝에 지워질 때 `TransactionPurgeService` 가 저장소 객체를 먼저 지운다.

## 이 문서를 고칠 때

**제한값을 바꾸면 그 값이 박힌 자리를 다 고친다.** 크기·형식은 문서·앱·`check` **세 곳**이고,
장수는 문서·앱·**트리거** 세 곳이다(`Q102`). 문서만 고치면 코드가 옛 값으로 계속 막는다.

**허용 목록에 형식을 더하는 것은 이 문서가 먼저다.** 코드에 먼저 들어가면
다음 사람이 그것을 관례로 본다(`CLAUDE.md` 「코드를 쓸 때 항상 지키는 것」).
