# 용어집

같은 것을 코드·문서·화면에서 같은 말로 부르도록 도메인 용어를 영문 정본으로 못박는다.

## 정본은 영문이다

코드·DB 컬럼·API 필드가 전부 영문이라 **영문 이름이 정본**이고 한글은 대역이다.
문서 본문은 한글로 쓰되, 용어가 처음 나올 때 영문을 괄호로 병기한다.

새 개념이 생기면 **코드를 쓰기 전에** 여기에 영문 이름을 정한다.
코드에 먼저 박히면 그 이름이 정본이 되고, 나중에 바꾸려면 마이그레이션이 붙는다.

## `seller` 는 조직 하나만 가리킨다

지금까지 `seller` 가 세 자리에서 다른 뜻으로 쓰였다.

| 자리 | 뜻 |
|---|---|
| `seller` 테이블 | 상품을 파는 조직 |
| `role.code = 'seller'` | 그 조직에서 일하는 사람의 역할 |
| `role_permission.scope = 'seller'` | 판정 범위 |

조직과 역할이 같은 이름이면 "seller 를 지운다" 가 조직 폐업인지 역할 회수인지 안 갈린다.

**`seller` 는 조직에만 쓴다.** 역할 이름에서 뺀다.

| 무엇 | 이름 | 상태 |
|---|---|---|
| 조직 | `seller` | 그대로 |
| 조직 소유자 역할 | `seller_owner` | `V3` 시드가 이 코드로 넣는다. 역할 이름에 `seller` 를 안 쓴다 |
| 조직 실무자 역할 | `seller_staff` | 아직 없다. 권한 범위가 청크 5a 에서 정해진다 |
| 판정 범위 | `scope = 'seller'` | 그대로. 조직 범위라는 뜻이라 어긋나지 않는다 |

## 조직과 사람

| 영문 | 한글 | 뜻 |
|---|---|---|
| `app_user` | 계정 | 로그인하는 개인. 사람 하나에 하나다 |
| `seller` | 셀러 | 상품을 등록하고 파는 조직. 상품과 정산의 주인이다 |
| `seller_member` | 소속 | 계정이 어느 셀러에 속하는지를 잇는 행 |
| `customer` | 고객 | 상품을 보고 주문하는 역할 |
| `seller_owner` | 셀러 대표 | 셀러의 상품과 주문을 다루고 멤버에게 역할을 주는 역할 |
| `seller_staff` | 셀러 담당자 | 셀러의 주문을 처리하되 멤버 구성은 못 바꾸는 역할 |
| `admin` | 관리자 | 모든 자원을 보고 역할과 권한을 편집하는 역할 |
| `auditor` | 감사자 | 모든 자원을 조회하고 아무것도 바꾸지 않는 역할 |

## 권한

| 영문 | 한글 | 뜻 |
|---|---|---|
| `role` | 역할 | 권한 묶음에 붙인 이름. 사람에게 붙는 것은 역할이고 권한이 아니다 |
| `permission` | 권한 | 자원 + 동작 한 쌍. `product:create` 같은 것 |
| `user_role` | 역할 부여 | 어느 계정에 어느 역할을 어느 셀러 범위로 줬는지 |
| `role_permission` | 권한 규칙 | 역할이 어떤 권한을 어느 범위에서 허용·거부로 갖는지 |
| `scope` | 범위 | 판정이 미치는 자원의 폭. `own`·`seller`·`all` |
| `effect` | 효과 | 규칙이 허용인지 거부인지. `allow`·`deny` |
| `field group` | 필드 그룹 | 응답 필드를 묶은 단위. 권한이 필드 단위까지 내려갈 때 쓴다 |
| `Decision` | 판정 | 허용 여부와 볼 수 있는 필드 그룹과 근거를 담은 결과 |

`own` 은 "내가 만든 것", `seller` 는 "내가 속한 셀러의 것", `all` 은 "전부" 다.

## 상품

| 영문 | 한글 | 뜻 |
|---|---|---|
| `product` | 상품 | 셀러가 파는 것 하나. 이름·설명·대표 가격이 붙는다 |
| `product_option` | 옵션 | 상품이 가르는 축. 색상, 사이즈 |
| `sku` | 판매 단위 | 옵션 조합 하나. 재고가 붙고 주문이 직접 가리킨다 |

"검정 M" 이 `sku` 고 그 티셔츠가 `product` 다. 재고와 주문은 항상 `sku` 를 본다.

## 주문과 결제

| 영문 | 한글 | 뜻 |
|---|---|---|
| `cart` | 장바구니 | 아직 주문 안 된 담기 목록 |
| `order` | 주문 | 고객이 확정한 구매 건. 결제와 별개로 존재한다 |
| `order_item` | 주문 항목 | 주문 안의 `sku` 하나. 이름과 가격을 박제한다 |
| `order_shipping_address` | 배송지 | 주문의 받는 사람 정보. 개인정보라 주문보다 먼저 파기된다 |
| `payment` | 결제 | 돈이 실제로 오간 기록 |
| `refund` | 환불 | 이미 받은 돈을 돌려주는 기록 |

## 돈

| 영문 | 한글 | 뜻 |
|---|---|---|
| `commission` | 수수료 | 플랫폼이 주문 항목마다 떼는 금액 |
| `commission_rate` | 수수료율 | 수수료를 계산하는 비율. 주문 시점 값을 박제한다 |
| `settlement` | 정산 | 셀러에게 월 1회 지급액을 확정해 넘기는 절차 |
| `payout` | 지급액 | 정산에서 셀러가 실제로 받는 금액 |

## 수명과 상태

| 영문 | 한글 | 뜻 |
|---|---|---|
| `status` | 업무 상태 | 그 자원이 업무상 어느 단계인지. 판매중, 품절, 배송중 |
| `deleted_at` | 수명 | 그 자원이 아직 존재하는지. 값이 있으면 삭제됐다 |

**둘을 한 컬럼에 섞지 않는다.** 근거는 `domain-model.md` 에 있다.

## 헷갈리는 짝

| 가르는 것 | 무엇이 다른가 |
|---|---|
| 취소 `cancel` / 반품 `return` | 취소는 배송 전, 반품은 배송 후. 기산점과 배송비 부담이 다르다 |
| 반품 `return` / 청약철회 `withdrawal` | 반품은 절차, 청약철회는 법이 준 권리. 기간과 제한 사유가 법으로 정해진다 |
| 환불 `refund` / 취소 `cancel` | 환불은 돈의 이동, 취소는 주문 상태의 전이. 취소해도 결제 전이면 환불이 없다 |
| 권한 `permission` / 역할 `role` | 권한은 동작 하나, 역할은 권한 묶음. 사람에게 붙는 것은 역할뿐이다 |
| 계정 `app_user` / 고객 `customer` | 계정은 로그인 주체, 고객은 그 계정이 가진 역할 하나 |
| 상품 `product` / 판매 단위 `sku` | 재고와 주문이 가리키는 것은 항상 `sku` 다 |
| 가격 `price` / 결제액 `paid_amount` | 가격은 상품에 붙은 값, 결제액은 할인과 배송비를 거친 실제 금액 |

## 쓰지 않는 말

| 쓰지 말 것 | 대신 | 왜 |
|---|---|---|
| 판매자, 입점사, 벤더 | 셀러 `seller` | 같은 것을 세 이름으로 부르면 검색이 안 걸린다 |
| 유저, 회원 | 계정 `app_user` | 사람과 계정을 가르는 자리가 있다 |
| 옵션 (`sku` 를 가리켜서) | 판매 단위 `sku` | `product_option` 이 이미 옵션이다 |
| 롤 | 역할 `role` | 음차와 번역을 섞으면 표기가 갈린다 |
| 소프트 딜리트 | 수명 컬럼 `deleted_at` | 방식 이름이 아니라 무엇을 담는 컬럼인지로 부른다 |

## 이 문서를 고칠 때

새 테이블이나 새 API 필드에 **이 표에 없는 개념**이 나오면 여기에 먼저 한 줄 넣는다.
기존 이름을 바꾸면 마이그레이션과 코드가 같이 움직여야 하므로 청크로 세운다.
