# 문서 지도

어떤 기준 문서가 필요하고, 어느 청크가 그 문서를 기다리는지 적는다.

## 왜 두나

청크 3b 까지 만들고 보니 결정이 코드에만 있었다.
"스코프는 넓은 쪽이 이기고 효과는 좁은 쪽이 이긴다" 가 `PermissionEvaluator` 안에 묻혀 있어서,
그 규칙을 알려면 코드를 읽어야 한다. 청크가 늘수록 이런 것이 쌓인다.

기준 문서는 **여러 청크가 같이 참조하는 결정**을 모아 둔다.
한 청크에서만 쓰는 결정은 ADR 로 남기고 여기 두지 않는다.

## 문서 종류

| 자리 | 무엇이 들어가나 |
|---|---|
| `doc/adr/` | 결정 하나와 그 근거. 한 번 쓰면 안 고치고, 뒤집으면 새 번호로 쓴다 |
| `doc/reference/` | 여러 청크가 참조하는 기준. 사실이 바뀌면 고친다 |
| `doc/guide/` | 손으로 따라 하는 절차. 아직 없다 |

기준 문서를 쓸 때 근거로 삼는 바깥 자료는 `external-references.md` 에 모아 뒀다.
링크와 확인 날짜가 거기 있다.

## 문서를 쓰는 순서

의존이 있다. 굵은 것이 다른 문서의 선행이다.

```
D1 용어집 ─┬─> D4 도메인 모델 ─> D7 상태머신
           └─> D3 비즈니스 모델 ─┬─> D8 금액 규약 ─> D19 배치
                                  └─> D13 수명 정책
D2 법 요건 ─────> D13 수명 정책
D5 API 규약 ─┬─> D12 이벤트 카탈로그
             └─> D20 화면 규약
D6 권한 명세 (D2·코드에서 뽑는다)
D14 보안 ─> D17 파일 규약
D15 테스트 · D16 관측 · D21 성능 (독립)
```

**D6 은 썼다.** 남은 것 중 급한 것은 D15 다. 테스트가 로컬 DB 에 묶여 있어서
Docker Desktop 을 끄면 전부 실패한다.

기준 자료는 `external-references.md` 에 있다. 링크를 실제로 열어서 확인했다.

| 문서 | 기준 자료 |
|---|---|
| D3 비즈니스 모델 | Stripe Connect |
| D4·D1 도메인 모델·용어집 | DDD Reference (Evans) |
| D5 API 설계 규약 | Zalando RESTful API Guidelines |
| D6 권한 모델 명세 | XACML 3.0 (개념만) |
| D8 금액·통화 | Money 패턴 (Fowler) |
| D9 식별자 | RFC 9562 UUID |
| D11 동시성·트랜잭션 | PostgreSQL 17 격리 수준 + Stripe 멱등 요청 |
| D12 이벤트 카탈로그 | Zalando Event 장. CloudEvents 는 **보류** — 청크 29·32 에서 정한다 |
| D14 보안 기준 | OWASP Top 10 + Cheat Sheet Series + Spring Security 7.1.0 |
| D15 테스트 전략 | Test Pyramid + Spring Boot 4.1.0 · Testcontainers 1.21.4 |
| D16 관측 규약 | Micrometer Tracing + W3C Trace Context 헤더 형식 |
| D17 파일·미디어 | OWASP File Upload Cheat Sheet |
| D21 성능 목표 | Google SRE Book — SLO 장 |

D7·D10·D13·D18·D19·D20 은 참조를 안 정했다. 표준이 없거나 우리가 정하는 비중이 커서다.
이유는 `external-references.md` 끝에 적혀 있다.

그중 D7·D10 은 자료 없이 정할 수 있는 것을 ADR 0009 에서 정했다.
공휴일은 임시공휴일 때문에 테이블에 두고, 주문 전이표는 도메인 규칙이라 코드에 둔다.

스타일 가이드는 하나만 고른다. 둘을 섞으면 같은 문제에 서로 다른 답이 들어와 규약이 충돌한다.

**정산을 하려면 D3 이 먼저다.** 수수료를 셀러에 둘지 상품에 둘지, 요율을 언제 박제할지가
정산 스키마의 모양을 정한다. 이건 만들면서 정할 수 없는 종류의 결정이다.

## 이 지도를 고칠 때

청크를 해 보고 "그 문서가 없어도 됐다" 거나 "다른 문서가 필요했다" 가 나오면 여기를 고친다.
문서를 다 쓰고 청크를 시작하는 것이 아니라, 청크가 막히는 자리에서 문서를 쓴다.
