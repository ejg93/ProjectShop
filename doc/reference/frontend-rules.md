# 프론트 계층 규약

화면 코드가 **어디서 돌고 서버를 어떻게 부르나**. `D23` 이 백엔드의 계층을 정했고
여기서는 프론트의 계층을 정한다.

**무엇을 보여주나는 `screen-rules.md`(D20)가 정한다.** 이 문서는 그것을 어느 층에서 그리나만 다룬다.

## 기준

| 대상 | 기준 자료 |
|---|---|
| 프레임워크 | Next 16 App Router. **`frontend/AGENTS.md` 가 `node_modules/next/dist/docs/` 를 읽으라고 지시한다** |

**기억으로 쓰면 틀린다.** Next 는 판마다 캐시 기본값과 API 가 갈렸고, 이 문서의 캐시 절은
번들된 문서를 읽고 확인한 것이다. 판을 올릴 때 그 절부터 다시 본다.

## 계층

```
서버 컴포넌트  →  api.ts  →  백엔드
   그린다         부른다      판정한다

클라이언트 컴포넌트  →  api.ts  →  백엔드
   누른다·입력한다
```

| 규칙 | 왜 |
|---|---|
| 서버를 부르는 곳은 `api.ts` 하나다 | 표기 변환·CSRF·오류 변환이 거기에만 있다. 우회하면 어떤 응답만 안 바뀐 채 화면에 닿는다(`D5`) |
| 화면은 역할 이름을 모른다 | 판정이 두 벌이 된다(`D20` 「권한 없는 것은 숨긴다」) |
| 화면은 동작↔경로 표를 안 든다 | 동작 이름의 소문자·하이픈이 곧 경로다(`D5`). 표를 들면 한쪽만 고쳐진다 |

## 서버 컴포넌트가 기본이다

**`"use client"` 를 안 붙인 것이 기본값이고, 붙이는 쪽이 근거를 댄다.**

기본을 반대로 두면 안 되는 이유가 `D23` 의 「기본이 열림이면 안 된다」와 같다 —
**아무 생각 없이 지나간 화면이 느린 쪽으로 떨어진다.**

### 클라이언트로 내리는 경우

아래 넷 중 하나가 필요할 때만 내린다. 그 외에는 서버에 둔다.

| 필요한 것 | 예 |
|---|---|
| 입력을 받는다 | 로그인 폼, 수량 고르기 |
| 상태를 들고 있는다 | 고른 옵션, 열린 대화상자 |
| 사용자 조작에 반응한다 | 버튼 누름, 토스트 |
| 브라우저 API 를 쓴다 | `document`, `localStorage` |

**경계를 잎사귀로 내린다.** 페이지 통째로 `"use client"` 를 붙이지 않고,
입력이 있는 조각만 클라이언트 컴포넌트로 뺀다. `/login` 이 그 모양이다 —
페이지는 서버 컴포넌트고 폼만 클라이언트다.

### 읽기는 서버, 쓰기는 클라이언트

| 무엇 | 어디 |
|---|---|
| 목록·상세를 그린다 | 서버 컴포넌트 |
| 담기·취소·발송을 누른다 | 클라이언트 컴포넌트 |

**쓰기를 서버 컴포넌트로 옮기지 않는다.** 서버 컴포넌트는 그리는 자리라 누른 결과를
화면에 반영할 수단이 없다.

## 서버를 부르는 입구가 셋이다

**밖에서 `fetch` 를 쓰지 않는다.** 변환·오류 처리·세션 운반이 여기에만 있다.

| 입구 | 어디서 도나 | 쿠키 | CSRF |
|---|---|---|---|
| `api()` | 클라이언트 컴포넌트 | 브라우저가 자동으로 붙인다 | 붙인다 |
| `apiPublic()` | 서버 컴포넌트 | **안 싣는다.** 누구에게나 같은 데이터 | 필요 없다 — 읽기만 한다 |
| `apiSession()` | 서버 컴포넌트 | **손으로 싣는다**(아래) | 필요 없다 — 읽기만 한다 |

**서버 입구를 둘로 가른 것은 캐시 때문이다.** 공개 데이터는 캐시를 켤 수 있고 사람마다 다른 것은
못 켠다. 한 함수에 옵션으로 두면 그 옵션을 빠뜨린 화면이 **남의 주문을 캐시한다.**

**`apiSession()` 만 파일이 다르다**(`api-session.ts`, 청크 15-1). `next/headers` 를 쓰는데
그것을 `api.ts` 에 들이면 **그 파일을 가져다 쓰는 클라이언트 컴포넌트가 전부 빌드에서 깨진다.**
변환과 오류 처리는 `api.ts` 것을 그대로 가져다 쓴다 — 두 벌이 되면 어떤 응답만 카멜로 바뀐다.

**주소가 다르다.** 브라우저 입구는 `/api/...` 상대경로라 rewrite 프록시를 지나고,
서버 입구는 Next 서버가 백엔드에 직접 붙어서 절대 주소가 필요하다.
그 값은 `next.config.ts` 와 같은 환경변수에서 온다.

**서버 입구는 읽기 전용이다.** 쓰기가 필요하면 클라이언트 컴포넌트에서 브라우저 입구를 쓴다.

## 인증이 필요한 데이터

`/orders`·`/me`·`/seller/*` 처럼 로그인해야 보는 화면도 **서버 컴포넌트로 그린다**(사용자 선택).
**서버 입구가 세션 쿠키를 손으로 실어 보낸다.**

```
브라우저 → [Next 서버]  cookies() 로 세션을 꺼내 헤더에 싣는다 → 백엔드
```

### 왜 이쪽인가

**첫 그림이 비지 않는다.** 내 주문은 사람마다 달라서 캐시가 안 걸린다. 클라이언트에서 부르면
`HTML → JS 내려받기 → JS 실행 → 요청 → 데이터` 를 거쳐 **들어갈 때마다 빈 뼈대를 먼저 본다.**

**화면군마다 다시 판단하지 않는다.** 「공개는 서버, 인증은 클라이언트」로 가르면
섞인 화면이 오는 순간 답이 없다 — 상품 목록에 "내가 찜했나" 가 붙으면 그 화면은 어느 쪽인가.

### 프론트가 세션을 해석하는 것이 아니다

**나르는 것과 읽는 것을 가른다.**

| 무엇 | 누가 |
|---|---|
| 쿠키 문자열을 헤더에 얹는다 | 브라우저·Next 서버 |
| **그 값이 누구인지 판정한다** | **백엔드만** |

`D14` 가 **서버 메모리 세션**으로 정해서 쿠키에 든 것은 뜻 없는 식별자다.
프론트가 열어도 나오는 것이 없다 — JWT 였으면 달랐다.

**신뢰 경계가 새로 열리는 것도 아니다.** rewrite 프록시가 이미 그 쿠키를 Next 서버로 통과시킨다.
바뀌는 것은 프레임워크가 조용히 하던 운반을 우리 코드가 하게 되는 것뿐이다.

### 401 도 그 입구가 잡는다

세션이 끊기면 `apiSession()` 이 **그 자리에서 로그인 화면으로 보낸다**(`redirect`).
예외로 올려서 화면마다 잡게 하면 한 화면이 빠뜨렸을 때 **그 화면만 조용히 빈 목록**이 된다.

보낼 때 `?reason=session-expired` 를 붙인다. **왜 나왔는지를 알려야 한다**(`D20`) —
설명 없이 로그인 화면이 나오면 사용자는 자기가 뭘 잘못 눌렀다고 생각한다.

403·404 는 안 잡는다. **그 화면이 무엇을 그릴지가 자원마다 달라서** 여기서 정할 수 없다.

**브라우저 입구도 같이 한다**(청크 15-2). 화면을 띄워 둔 사이에 세션이 끊기면 401 이 거기서 나는데,
잡지 않으면 **「결제하지 못했습니다」 같은 엉뚱한 문구**가 뜨고 사용자는 카드를 의심한다.
층이 둘이라 코드가 두 군데인 것이지 규칙이 둘인 것이 아니다.

**로그인·가입 경로는 뺀다.** 거기서 나는 401 은 「세션이 없다」가 아니라 「이번 시도가 틀렸다」다 —
보내 봐야 같은 화면이고, 그 폼은 어느 칸도 지목하지 않는 오류로 그려야 한다(`D20`).

### 로그인해야 보는 화면은 그리기 전에 막는다

`D20` 화면 지도가 「로그인」이라고 적은 화면은 **서버 컴포넌트가 먼저 확인한다.**
자원 조회가 우연히 비로그인에도 열려 있으면(장바구니가 그렇다) 화면이 다 그려진 다음
**버튼을 눌러야 401 이 난다** — 그때는 이미 배송지를 다 적은 뒤다.

확인은 `apiSession('/api/me')` 한 번이면 된다. 401 이면 그 입구가 알아서 보낸다.

### 그래서 운반을 한 군데에 가둔다

우리 코드가 만지기 시작하면 실수 셋이 새로 가능해진다.

| 실수 | 무슨 일이 나나 |
|---|---|
| 세션 값을 로그에 찍는다 | 탈취 재료가 로그에 남는다(`D16` 이 금지) |
| 결과가 캐시된다 | **남의 주문이 보인다**(아래 절) |
| 백엔드 아닌 곳에 싣는다 | 세션이 밖으로 나간다 |

셋 다 **만지는 자리가 여럿일 때** 나는 사고다. 그래서 서버 입구 하나에만 둔다.

**나르는 쿠키를 목록으로 가둔다.** 요청에 온 것을 통째로 넘기면 나중에 프론트가 자기 쿠키를
하나 만들었을 때 그것까지 백엔드로 샌다. 지금 목록은 둘이다.

| 쿠키 | 왜 나르나 |
|---|---|
| `SHOPSESSION` | 로그인한 사람이 누구인지. 판정은 백엔드가 한다 |
| `CART-TOKEN` | **장바구니는 로그인 전에도 사는 자원**이다(청크 9). 이것 없이는 비로그인 장바구니가 서버 컴포넌트에서 빈 채로 그려진다 |

## 캐시 — 실수하면 남의 것이 보인다

**이 절은 번들된 Next 문서를 읽고 쓴 것이다.** 아래 셋이 근거다.

| 사실 | 어디 |
|---|---|
| `cookies()` 는 Request-time API 라 그 라우트를 **dynamic 으로 만든다** | `04-functions/cookies.md` |
| `cacheComponents` 를 안 켜면 **`fetch` 는 기본이 캐시 안 됨** | `02-guides/caching-without-cache-components.md` |
| **`dynamic = 'force-static'` 은 `cookies()` 가 빈 값을 돌려주게 만든다** | 같은 문서 |

셋째가 위험하다. **세션이 사라지는데 오류가 안 난다** — 그냥 비로그인으로 그려진다.

### 지키는 것

| 규칙 | 왜 |
|---|---|
| 인증 데이터를 그리는 라우트에 `dynamic = 'force-static'` 을 안 건다 | 세션이 조용히 빈 값이 된다 |
| 같은 라우트에 `fetchCache = '*-cache'` 를 안 건다 | 사람마다 다른 응답이 공유된다 |
| **인증 요청에는 `cache: 'no-store'` 를 명시한다** | 아래 |
| 캐시를 켜는 것은 **공개 데이터에만** | 상품 목록·상세는 누구에게나 같다 |

**기본값에 기대지 않는 이유**가 있다. 같은 Next 문서 안에서 서술이 갈린다 —
머리말은 "기본이 캐시 안 됨" 인데 `fetchCache` 절은 "Request-time API 앞의 `fetch` 는 캐시된다"
고 적혀 있다. **어느 쪽이 맞든 명시하면 안전하다.**

`cacheComponents` 플래그를 켜기로 하면 **이 절을 통째로 다시 본다.** 켜는 순간 기본 동작이 바뀐다.

## 상태는 주소에 둔다

목록의 페이지·필터·정렬은 **URL 검색 문자열**에 둔다. 컴포넌트 상태로 들지 않는다.

`D20` 이 번호 페이징을 고른 이유와 같다 — **주소가 곧 상태**라야 뒤로 가기·새로고침·링크 공유가
저절로 된다. 그리고 서버 컴포넌트가 그 값을 읽어서 그릴 수 있다.

**클라이언트 상태는 화면 안에서만 사는 것에 쓴다.** 고른 옵션, 열린 대화상자, 입력 중인 값.

## 오류를 어느 층이 잡나

**어디에 보여주나는 `D20` 이 정했다.** 여기서는 잡는 층만 정한다.

| 오류 | 어디서 잡나 |
|---|---|
| 입력값이 규칙에 안 맞음 | 그 폼의 클라이언트 컴포넌트 |
| 401 | **입구.** 로그인 화면으로 보낸다 — 서버 입구든 브라우저 입구든 같다 |
| 403·404 | 그 화면의 서버 컴포넌트. 페이지 전체를 바꿔 그린다 |
| 5xx | 라우트의 오류 경계 |

**`type` 으로 갈린다. 상태 코드나 `detail` 문자열로 안 갈린다**(`D5`·`D20`).

## 2026-08-20 규약 대조에서 나온 것

**아직 안 고쳤다**(사용자 선택) — 축 여섯을 다 훑은 뒤에 한꺼번에 처분한다.

**`P4` — 위 「오류를 어느 층이 잡나」의 마지막 줄에 잡을 자리가 없다.**

표는 5xx 를 「라우트의 오류 경계」가 잡는다고 정했는데 **`error.tsx` 가 한 개도 없다.**
403 도 「그 화면의 서버 컴포넌트가 페이지 전체를 바꿔 그린다」인데, `apiSession` 이 던진
`ApiError` 를 잡는 화면이 없어서 그대로 위로 올라간다.

그러면 **Next 기본 오류 화면**이 뜬다 — 우리 셸도 없고 문구도 우리 것이 아니고,
`D20` 「문구」가 정한 존댓말도 안 걸린다.

| 표가 정한 것 | 실제 |
|---|---|
| 401 → 입구가 로그인으로 보낸다 | **선다.** `api.ts`·`api-session.ts` 둘 다 |
| 403·404 → 그 화면이 페이지 전체를 바꿔 그린다 | 404 만 선다(`not-found.tsx`). **403 은 없다** |
| 5xx → 라우트의 오류 경계 | **없다.** `error.tsx`·`global-error.tsx` 0개 |

**두 칸이 파일 자체가 없어서 안 지켜진다.** 규약이 틀린 것이 아니라 아직 안 만든 것이고,
그 사실이 어디에도 안 적혀 있어서 **다 지킨 것처럼 보인다.**

## 이 문서를 고칠 때

화면을 만들다가 여기 없는 상황이 나오면 **그 상황을 여기 먼저 추가한다.**
청크마다 다르게 정하면 화면 수만큼 규칙이 생긴다.

**Next 판을 올릴 때 「캐시」 절을 먼저 확인한다.** 그 절만 판에 묶여 있다.
