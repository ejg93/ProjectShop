# 1차 점검

청크 0(저장소 뼈대)부터 5-1(인증 기반)까지를 2026-08-07 에 한 번에 훑었다.
개별 청크가 제대로 됐는지는 각 청크의 테스트가 이미 본다. 여기서 보는 것은 **그 위층**이다 —
진도, 문서와 코드의 비율, 청크 규칙이 지켜지는지, 미룬 것이 추적되는지.

| 항목 | 값 |

| PLAN 의 청크 (유니크) | 128 |
| 완료 | 30 (23%) |

| 문서 | 4,686줄 (`doc/` 4,121 + 루트 565) |

## 발견 — 고칠 것

### 1. `PLAN.md` 의 청크 표가 한 줄 깨져 있었다

160행에서 청크 3d 행 끝에 청크 4(권한 판정 엔진) 행이 붙어 있었다.
청크 4 는 이미 완료돼서 실행에는 지장이 없었지만, **표를 훑어 다음 청크를 고르는 재개 절차가 이 행을 못 본다.**
미완료 청크에 같은 일이 생기면 그 청크는 계획에서 조용히 사라진다.

이번 점검에서 고쳤다.

### 2. 이력의 커밋 해시가 여러 줄 비어 있었다

`PROGRESS.md` 이력에서 4a·4b·5-1 행의 커밋 칸이 비었다. 4a 의 해시는 바로 아래
"4a 중 드러난 것" 행에 붙어 있었다. 청크와 커밋을 1:1 로 대조할 수 없는 상태였다.

이번 점검에서 채웠다.

### 3. 청크 규칙(파일 1~3개)이 절반만 지켜졌다

커밋 52개의 변경 파일 수 분포.

| 파일 수 | 커밋 |
|---|---|
| 1~3 | 28 (54%) |
| 4 | 12 |
| 5 이상 | 12 |

4개짜리 12건은 대부분 `PLAN.md`·`PROGRESS.md` 두 기록 파일이 같이 물려서 나온 수다.
실질 작업 파일은 2개인 셈이라 규칙 취지에는 안 어긋난다.
5개 이상 12건이 실제 초과다.

## 발견 — 구조

### 4. 23% 왔는데 사용자가 쓸 수 있는 기능이 0개다

엔드포인트가 `GET /api/health` 하나뿐이다. 권한 축을 먼저 깊게 판 결과다.

권한 판정 엔진·감사 로그·필드 마스킹·캐시가 전부 **호출자 없이** 서 있다.
테스트가 직접 부르는 것 말고는 이 코드를 지나가는 경로가 없다.
설계가 실제 요청 흐름에서 맞는지는 아직 한 번도 확인되지 않았다.

`4b-1`(감사 로그 조회), `8a`(내 권한 목록)이 그 검증을 맡는 청크인데 둘 다 미착수다.

### 5. 테스트가 main 의 2.7배다

지금은 정상이다. main 이 판정 엔진뿐이고 엔드포인트가 없어서 분모가 작다.
청크 5~8 에서 API 가 붙으면 비율이 내려간다. **안 내려가면** 그때는 신호다.

### 6. 계획이 8배로 불었다

초기 16청크에서 128청크가 됐다. 계획을 늘린 청크가 5번 있었다
(`0-1`, `3-1`, `3a-1`, `3a-2`, `4d-1`).

늘어난 이유는 매번 달랐고 그때마다 근거가 ADR 에 남아 있다.
다만 **계획 확장 자체가 청크를 소비한다**는 점은 기록해 둘 값이 있다.
5번 중 4번이 코드를 한 줄도 안 쓴 청크였다.

### 7. 미룬 것은 추적되고 있다

`document-map.md` 가 미착수 문서(D12·D17~D21)를 청크에 걸어 뒀고,
`permission-rules.md` 의 「알려진 구멍」은 3개가 남아 있다.
4번째였던 "user 필드그룹 미연결" 은 `V7` 로 고치고 문서에서 지웠다 — 추적이 도는 상태다.

## 결정이 필요한 것

점검이 답을 못 내는 자리다. 아래 둘은 사용자가 정한다.

| 무엇 | 갈림 |
|---|---|
| 청크 규칙의 파일 수 | 기록 파일 2개를 세지 않기로 하면 규칙과 현실이 맞는다. 아니면 5개 이상이 나오는 청크를 계속 쪼갠다 |
| 다음 순서 | 권한 축을 계속 파느냐, 아니면 얇게라도 요청이 관통하는 경로를 먼저 내서 설계를 검증하느냐 |
