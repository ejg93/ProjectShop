# 실서비스였다면 — 비교 메모

이 저장소의 결정들이 「로컬 전용·서버 1대·실사용자 없음」이라는 전제에 얼마나 매달려 있는지를
전제별로 갈라서 적는다.

**이 파일은 청크 실행 때 안 본다.** 기준 문서가 아니라 읽을거리다.
여기 적힌 것을 근거로 코드를 쓰지 않는다.

등급은 셋으로 나눈다.

| 등급 | 뜻 |
|---|---|
| **지금** | 이 저장소가 실제로 정한 것 |
| **실서비스** | 사용자가 있고 돈이 오가는 일반 커머스 |
| **규제** | 금융·의료처럼 심사와 감사가 붙는 곳 |

---

## 먼저: 등급이 올라가도 안 바뀌는 것

**절반쯤은 안 바뀐다.** 규모가 아니라 옳고 그름의 문제라서다.

| 결정 | 왜 안 바뀌나 |
|---|---|
| 수명(`deleted_at`)과 업무 상태(`status`)를 안 섞는다 | 섞으면 복구할 때 이전 상태를 잃는다. 규모와 무관하다 |
| 시각은 UTC 로 저장하고 판단만 KST | 시간대를 섞으면 하루 경계가 어긋난다 |
| 계산한 기한은 박제한다 | 기준이 바뀌어도 과거가 안 바뀌어야 한다 |
| 수수료율을 주문 시점에 박제한다 | 같은 이유 |
| 배치 기준 시각을 고정한다 | 재실행 결과가 같아야 한다 |
| 금액은 정수로 저장한다 | 부동소수점은 규모와 무관하게 틀린다 |
| 재고는 조건부 UPDATE | 읽고 검사하고 쓰는 방식은 어디서든 깨진다 |
| 로그에 개인정보 대신 식별자만 | 상위 등급의 방식이 이쪽이다. 마스킹은 빠뜨리면 샌다 |
| 순번을 주문번호로 노출하지 않는다 | 거래량이 새는 건 규모가 클수록 더 아프다 |
| 권한을 데이터로 두고 판정을 한 군데서 | 코드에 흩으면 규모가 커질수록 못 고친다 |
| 오류 본문에 `trace_id` | 문의를 로그로 잇는 값싼 방법이다 |

**나머지가 전제에 매달린 것들이다.** 아래가 그 목록이다.

## D14 보안

### 비밀번호 해시

| | 값 | 근거 |
|---|---|---|
| 지금 | bcrypt cost 10 | 해시 DB 유출 시나리오가 실재하지 않는다 |
| 실서비스 | bcrypt cost 12~13 | 여기도 대부분 bcrypt 다. cost 를 올려 100ms 안팎을 맞춘다 |
| 규제 | argon2id + **페퍼** | 페퍼를 앱 밖 키 저장소(KMS·HSM)에 둔다. DB 만 털려도 해시를 못 깬다 |

페퍼가 진짜 차이다. 알고리즘을 바꾸는 것보다 **키를 DB 밖에 두는 것**이 유출 시나리오를 바꾼다.

### 비밀번호 규칙

| | 값 |
|---|---|
| 지금 | 길이 8~64, ASCII 만 |
| 실서비스 | + **유출 목록 대조**. HIBP 의 k-anonymity API 는 해시 앞 5자리만 보내서 비밀번호를 안 넘기고 조회한다 |
| 규제 | **복잡도 강제가 규정에 남아 있는 곳이 많다** |

규제 등급이 오히려 NIST 와 반대로 간다. 심사 항목에 박혀 있으면 근거와 무관하게 맞춰야 한다.
"보안이 세다" 와 "규정을 통과한다" 가 늘 같지는 않다.

### 세션

| | 값 | 붙는 것 |
|---|---|---|
| 지금 | 서버 메모리 | — |
| 실서비스 | Redis | 서버를 늘리고 재기동을 버틴다 |
| 규제 | + 동시접속 1개 제한, 민감 작업 전 재인증, 타임아웃 10~15분 | 재인증은 화면 흐름이 통째로 늘어난다 |

### 로그인 실패 제한

| | 값 |
|---|---|
| 지금 | (계정, IP) 5회 / 15분 자동 해제 |
| 실서비스 | + CAPTCHA, 디바이스 지문, 새 기기 로그인 알림 |
| 규제 | **계정 잠금 + 관리자 해제**, 로그인 알림 의무 |

**여기서 진짜 비용은 돈이 아니라 사람이다.** 관리자 해제를 고르면 해제해줄 사람이 항상 있어야 한다.
자동 해제를 고른 이유가 그 사람이 없어서다.

### 전송 구간

| | 값 |
|---|---|
| 지금 | http. 쿠키 `Secure` 를 끈다 |
| 실서비스 | https 강제, HSTS, `Secure` 켬 |
| 규제 | + `__Host-` 접두사, 쿠키 도메인 고정, TLS 버전·암호군 지정 |

**이 저장소에서 가장 위험한 항목이다.** 전제가 깨지는 순간 세션 쿠키가 평문으로 흐른다.

### 아예 없는 것

| 항목 | 실서비스에서 |
|---|---|
| 2단계 인증 | 관리자 계정에는 사실상 필수 |
| 의존성 취약점 스캐너 | CI 에 Dependabot·OWASP Dependency-Check |
| 침투 테스트 | 연 1회 외부 업체 |
| 시크릿 관리 | `.env` 대신 Vault·AWS Secrets Manager |

## D11 동시성

| 항목 | 지금 | 실서비스 | 규제·금융 |
|---|---|---|---|
| 재고 | 조건부 UPDATE | 같다. 트래픽이 크면 Redis 재고 + 비동기 반영, 또는 재고 예약 | 해당 없음 |
| 격리 수준 | Read Committed | 같다 | 원장은 **Serializable** 또는 명시적 락. 잔액에 팬텀이 끼면 회계가 안 맞는다 |
| 멱등키 보관 | 24시간 | 24시간~7일 | **영구.** 감사 대상이라 못 지운다 |
| 재시도 | 앱 안에서 3회 | + 데드레터 큐 | + 실패 건 수동 처리 화면 |

재고 예약(장바구니에 담을 때 잡아 두기)을 안 한 게 전제에 매달린 것이다.
트래픽이 몰리는 실서비스에서는 "결제 직전에 품절" 이 이탈로 직결돼서 예약을 넣는다.
대신 만료 배치와 예약 재고 회계가 통째로 붙는다.

## D16 관측

| 항목 | 지금 | 실서비스 | 규제 |
|---|---|---|---|
| 형식 | 텍스트 | **JSON + 수집기**(Loki·ELK). 서버가 여럿이면 텍스트로는 못 뒤진다 | + 로그 무결성(WORM 저장), 보관 기간 강제 |
| 추적 | `traceparent` 형식만 | OpenTelemetry 실제 연동, 분산 추적 화면 | + 감사 추적을 별도 계통으로 |
| 인증 실패 | INFO | 같다 | **별도 보안 로그 + SIEM**, 이상징후 자동 탐지 |
| 지표 | 없음 | Prometheus + Grafana, 알림 규칙 | + SLA 보고서 |
| 알림 | 없음 | PagerDuty·Slack, 당번 순번 | + 장애 보고 의무 |

로그 보관 기간이 규제에서 실제로 갈린다. 전자금융은 1년, ISMS-P 는 6개월 이상 같은 식으로
숫자가 박혀 있어서 스토리지 비용이 설계에 들어온다.

## D3 비즈니스 모델

| 항목 | 지금 | 실서비스 |
|---|---|---|
| 수수료 | 일괄 10%, 상품 예외 | 카테고리별 차등, 프로모션 요율, 셀러 등급제 |
| 정산 | 월 1회 | 주 1회 또는 일 정산. 셀러 현금흐름이 걸린 문제다 |
| 지급 | 계산만 | **PG·펌뱅킹 연동**, 실제 이체, 이체 실패 처리 |
| 세금 | 없음 | 세금계산서 발행, 부가세 신고 자료, 원천징수 |
| 정산 분쟁 | 없음 | 이의제기 창구, 보류 잔액, 지급 정지 |

**결제와 정산이 실서비스와 가장 크게 벌어지는 자리다.**
모의 PG(청크 12)는 흉내만 내고, 실제로는 PG 계약·정산 대사·미수금 관리가 따라온다.

| 전체 개수 | 항상 준다 | 큰 테이블에서는 `count(*)` 가 비싸서 근사치를 주거나 안 준다 |

## 아예 다루지 않는 축

이 저장소에 청크조차 없는 것들이다. 실서비스에서는 이쪽이 일의 절반이다.

| 축 | 내용 |
|---|---|
| 배포 | 무중단 배포, 롤백, 마이그레이션 순서, 카나리 |
| 백업 | 정기 백업, **복구 훈련**. 복구해 본 적 없는 백업은 백업이 아니다 |
| 가용성 | DB 이중화, 장애 조치, 헬스체크 기반 자동 교체 |
| 용량 | 트래픽 예측, 스케일 정책, 비용 관리 |
| 고객 지원 | CS 도구, 주문 강제 조정, 환불 예외 처리 |
| 법무 | 약관 개정 고지, 분쟁 대응, 통신판매업 신고 |
| 조직 | 온콜 당번, 장애 회고, 변경 승인 |

## 정리

이 저장소가 실서비스와 갈리는 지점을 한 줄로 줄이면 이렇다.

**결정 자체가 틀린 것은 거의 없고, 결정에 붙은 전제가 좁다.**

- 「서버 1대」가 세션·로그 형식·분산 락을 정했다
- 「로컬 전용」이 TLS·쿠키 `Secure`·시크릿 관리를 정했다
- 「실사용자 없음」이 해시 비용·유출 목록·2FA 를 정했다
- 「돈이 안 움직임」이 정산·세금·PG 를 흉내로 남겼다

전제 하나가 깨지면 그 전제에 매달린 것만 다시 보면 된다.
기준 문서마다 전제를 같이 적어 둔 이유가 이것이다.
